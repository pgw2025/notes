# 笔记热力图功能设计方案

- 状态：已实施（数据源有调整，见 §7）
- 日期：2026-09-16
- 关联文档：[checklist.md](./checklist.md)

## 1. 背景与目标

为笔记软件增加 GitHub 风格的活跃热力图，直观展示用户每天的笔记编辑强度。本方案仅涉及设计，不包含代码改动。

项目现状（已确认）：
- note 实体已有 `createdAt` / `updatedAt` 两个 ISO 时间戳字段
- 已有 `Timeline.vue` 时间线视图，按日期分组展示笔记
- 架构为本地优先：IndexedDB 存储 + 同步引擎 + 统一 service 层
- UI 基于 Vue 3 + Vant，同时支持移动端与桌面端

## 2. 需求决策（已与用户确认）

| 决策点 | 结论 |
|---|---|
| 统计口径 | 每天「编辑过的笔记数」（按 `updatedAt` 去重计数） |
| 入口位置 | `Timeline.vue` 顶部 |
| 默认时间范围 | 近 12 个月（GitHub 风格 7 行 × 53 周矩阵） |

## 3. 核心设计

### 3.1 统计口径定义

- 某天热度 = 当天 `updatedAt` 属于该自然日（本地时区）的笔记数，每篇笔记每天只计一次
- 存储字段为 ISO UTC 时间，聚合时必须先转换为本地时区再按天分组，避免跨时区日期错位
- 已删除笔记不参与统计（IndexedDB 中不保留或已被快照对账移除）

### 3.2 数据源：本地优先

- 直接从 IndexedDB 读取笔记（与导出功能一致，天然包含未同步的本地修改，离线可用）
- 后端零改动；不新增服务端聚合 API
- 一致性说明：热力图表达的是「活跃趋势」，本地与服务器快照的微小偏差可接受，同步完成后自然收敛

### 3.3 数据流

```
IndexedDB(notes, updatedAt 索引)
  → useHeatmap composable：游标范围查询 + 本地时区按天分组
  → 输出 53 周 × 7 天网格数据（含每日计数与 5 档色阶 level）
  → Heatmap.vue 渲染 SVG 矩阵
  → 点击格子 → 通知 Timeline.vue 按当天日期筛选笔记列表
```

### 3.4 聚合算法

- 用 IndexedDB 的 `updatedAt` 索引做下界查询（一年前时间点），游标遍历，避免全表扫描
- 每次遍历仅取 `updatedAt` 字段，不读取 content，降低内存与 IO 开销
- 按本地自然日分组计数，映射到 53 周 × 7 天网格
- 色阶映射采用固定阈值（如 0 / 1–3 / 4–6 / 7–9 / ≥10），比动态分位数更稳定、解释成本低；后续如需可改为分位数
- 千级笔记量下单次聚合为毫秒级，无需维护聚合表（不引入「按日期计数表」，避免写入路径改造）

### 3.5 组件设计

| 文件 | 类型 | 职责 |
|---|---|---|
| `composables/useHeatmap.js` | 新增 | 聚合查询、色阶映射、网格数据生成 |
| `components/Heatmap.vue` | 新增 | SVG 矩阵渲染、tooltip、图例过滤、点击回调 |
| `views/Timeline.vue` | 修改 | 顶部集成 Heatmap，接收格子点击事件并筛选当天笔记 |

Heatmap.vue 交互：
- hover / 键盘聚焦格子：显示 tooltip（日期、篇数、强度级别），高亮当前格子并弱化其余
- 图例 5 档色块：hover 高亮对应级别格子；点击锁定过滤，再点取消
- 点击非空格子：emit 事件携带当天日期，Timeline 筛选出当天笔记列表
- 空数据：显示空状态提示，不渲染空矩阵

### 3.6 移动端适配

- 12 个月矩阵宽度超出屏宽，外层用横向滚动容器（复用项目已有的移动端滚动经验：固定高度 flex 布局、`-webkit-overflow-scrolling: touch`、底部安全区避让）
- 行标签（一~日）与月标签保持可见；tooltip 在窄屏下避免溢出（随指针移动并钳位在容器内）

### 3.7 主题适配

- 色阶基于 CSS 变量，跟随项目已有的 theme store（深/浅色）自动切换
- 强度用同一品牌色系渐变，不使用语义色

## 4. 不做的事（明确排除）

- 不统计编辑次数（需编辑埋点事件表，存储膨胀，首版不做）
- 不统计字数增量（需内容快照对比，改动大收益有限）
- 不新增服务端聚合 API（后端零改动）
- 不引入按日期聚合表（写入路径改造风险大，当前数据量无必要）
- 不做年度多页切换（默认 12 个月单页展示）

## 6. 风险与注意事项

- 时区处理是首要风险点：所有聚合必须先转本地时区，验收时需覆盖 UTC 边界（如北京时间 00:00 前后）
- 大笔记库性能：必须走 `updatedAt` 索引范围查询，禁止全表遍历；如未来笔记量达十万级再考虑聚合表
- 与现有时间线列表的筛选状态需保持一致，避免热力图筛选与时间线自带筛选冲突

## 7. 实施调整记录（2026-09-16）

实施时核对代码库发现：当前前端为**纯服务端数据获取**架构，不存在 IndexedDB
本地数据层 / `dataService` / `localdata:changed` 事件（原方案基于历史「本地优先」
架构假设）。据此调整如下：

| 原方案 | 实际实施 | 原因 |
|---|---|---|
| IndexedDB 按 `updatedAt` 索引范围查询聚合 | 复用 `/notes/timeline` 接口，传 `fromDate`（一年前）拉取后前端聚合计数 | 与时间线列表同口径、零后端改动、天然包含删除过滤 |
| 本地时区分组 | UTC 日期分组（与服务端 `UpdatedAt.Date` 一致） | 保证点击格子筛选的日期与列表分组严格对应，不串天 |
| `localdata:changed` 事件刷新 | 每次进入页面重新挂载时 `onMounted(load)` 重新拉取 | Timeline 未启用 keep-alive，事件在当前代码库不存在 |
| 后端零改动 | 后端零改动 | 满足 |

交互按原方案完整实现：tooltip（日期/篇数/强度）、图例 hover 预览 +
点击锁定/取消（其他级别弱化）、点击格子联动当天筛选、空状态、深浅主题两套色阶。

遗留说明：
- 色阶固定阈值 0 / 1–3 / 4–6 / 7–9 / ≥10，与服务端按天计数对齐
- 每次进入时间线页面会额外发起一次 timeline 请求（仅 `fromDate`，复用现有端点）
